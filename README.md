# SO-ARM100 路径规划仿真

基于 **Pinocchio** 物理引擎和 **Meshcat** 可视化工具的 SO-ARM100 六自由度机械臂路径规划仿真项目。

## 项目概述

本项目实现了 SO-ARM100 机械臂的正/逆运动学求解、轨迹插值、RRT 避障路径规划以及 Meshcat 3D 可视化。支持从抓取点到放置点的完整规划流程，包含基座位置自动调整、工作空间检测等辅助工具。

## 各模块说明

### `kinematics.py` — 运动学求解器

封装 Pinocchio 的正/逆运动学接口：

- **正运动学 (FK):** 输入关节角 `q`，输出末端位置 `(3,)` 和旋转矩阵 `(3,3)`
- **逆运动学 (IK):** 阻尼最小二乘法 (`Jᵀ(JJᵀ + λ²I)⁻¹`)，防止奇异点附近关节角跳变，支持多初值重试

### `trajectory.py` — 轨迹规划

核心规划模块，包含：

- **插值方式:** 五次多项式插值 (`quintic`) / 抛物线过渡插值 (`parabolic`)，支持多段路径串联
- **RRT 避障:** 基于快速随机扩展树的避障路径搜索，支持多次尝试取最优
- **腕部 IK (`_solve_wrist_only`):** 固定手臂关节 (q[0:3])，只解算腕部关节 (`wrist_flex`, `wrist_roll`)，使末端达到目标位姿
- **释放姿态计算 (`_compute_release_q`):** 通过旋转矩阵 `R_x(-π/2)` 使夹爪关节轴线竖直（公垂线水平），确保物体释放时姿态正确

### `sim_test.py` — 主仿真程序

完整的抓取 → 放置 → 返回流程：

1. 定义世界坐标系下的目标位置和放置盒子位置
2. 自动搜索可达的基座偏移量
3. 将世界坐标转换到机器人坐标系
4. 添加障碍物和场景物体到 Meshcat 可视化
5. 调用 `Trajectory.plan()` 进行完整路径规划
6. 执行轨迹动画 → 释放物体 → 原路返回

### `check_workspace.py` — 工作空间检测

- 随机采样关节角 (默认 50000 点) 分析末端可达范围
- `check_reachability()`: 从多个随机初始猜测出发，统计 IK 成功率

### `base_adjust.py` — 基座位置调整

在以原点为中心的正方形区域内网格搜索，找到使所有目标点均可达的基座偏移量。

### `object.py` / `obstacle.py` — 可视化辅助

在 Meshcat 场景中添加/管理目标物体、放置盒子和障碍物。

## 使用说明

### 依赖

```bash
pip install pinocchio meshcat numpy
```

### 运行仿真

```bash
python sim_test.py                    # 默认五次多项式插值
python sim_test.py --method quintic   # 五次多项式插值
python sim_test.py --method parabolic # 抛物线过渡插值
```

仿真启动后会自动打开浏览器窗口: `http://127.0.0.1:7000/static/`

### 运行测试

```bash
python test_move.py           # 快速运动测试
python test_kinematics.py     # 运动学单元测试
python check_workspace.py     # 工作空间检测
```

## 关节索引

| 索引 | 关节名 | 说明 |
|------|--------|------|
| q[0] | shoulder_pan | 肩部旋转 |
| q[1] | shoulder_lift | 肩部抬升 |
| q[2] | elbow_flex | 肘部弯曲 |
| q[3] | wrist_flex | 腕部俯仰 |
| q[4] | wrist_roll | 腕部旋转 |
| q[5] | gripper | 夹爪 (0=闭合, 1.74533=全开) |

## 技术细节

### 物体释放的姿态控制

物体释放时只调节 `wrist_flex`(q[3]) 和 `wrist_roll`(q[4]) 两个腕关节，保持手臂 (q[0:3]) 不变。通过 `_solve_wrist_only()` 方法固定前三个关节的雅可比列，只解算腕部，使得：
- 夹爪关节轴线竖直（公垂线水平）
- 释放位置精确（腕部调整后末端位置偏差通常在 1cm 以内）

### RRT 参数

- 最大迭代次数: 2000
- 步长: 0.1 (关节空间)
- 目标偏置概率: 10%
- 分段阈值: 关节空间距离小于 0.2 时跳过 RRT（直接连接）

## 已知问题与待改进

### 1. 机械臂最后一个关节的取向问题

机械臂的最后一个关节（`wrist_roll`）最后总是竖直，而应该水平

### 2. 避障逻辑不完整

- RRT 碰撞检测基于关节空间采样，没有考虑连杆的连续扫掠体积 (Swept Volume)
- 仅检测离散点是否碰撞，可能遗漏路径中间段的碰撞
- 没有对障碍物做膨胀处理（当前有一个 margin 参数但未经充分测试）
- 没有考虑自碰撞检测

### 3. 夹取物体的逻辑需要改进

目前夹爪的闭合是开环控制（在轨迹中预设夹爪角度变化），无法感知是否真正夹紧。改进思路：

- **实时检测:** 如果夹爪角度在到达目标位置后长时间没有变化（未继续闭合），说明已经夹紧物体
- 需要结合更完善的物理引擎来实现触觉反馈

### 4. 物理引擎不完善

目前的"仿真"本质上是纯运动学展示（通过 Meshcat 显示关节角变化），没有物理模拟：

- 没有刚体动力学（碰撞响应、摩擦力、重力补偿）
- 夹爪与物体之间没有交互（物体只是场景中的一个静态几何体）
- 无法模拟真实抓取中的滑动、变形等情况
- 可以考虑集成 MuJoCo 或 Bullet 等物理引擎

### 5. 未实现实时规划

- 当前采用的是"先规划后执行"的开环架构，轨迹一旦生成就不再修改
- 没有实现 Model Predictive Control (MPC) 或 Receding Horizon Planning
- 未来可以探索：
  - 基于当前视觉反馈的动态重规划
  - 快速响应的在线轨迹生成
  - 在检测到环境变化时中断当前轨迹并重新规划

## 物体释放的思路

当前物体释放时只调 `wrist_flex` 和 `wrist_roll`（最后两个定位轴线），让它们的公垂线水平，具体实现：

1. 在 `plan()` 中生成笛卡尔路径点，第 4 个路径点为释放点位置
2. 先用完整 IK 求解所有路径点（统一使用单位姿态 `np.eye(3)`）
3. 对释放点，调用 `_compute_release_q()`：
   - 构建 `R_x(-π/2)` 旋转矩阵使夹爪轴线竖直
   - 先用完整 IK 重新求解（以 approach 姿态为初值加速收敛）
   - 若失败则 fallback 到只调腕部 (`_solve_wrist_only`)
4. 验证腕部调整后的末端位置偏差

这个方案的优势是手臂主体不动，只靠腕部微调就能完成释放姿态变换，既保证了释放位置的精度，又避免了全关节重新规划带来的碰撞风险。
